# Architecture and behavior contracts

## Board and puzzle

- A board is a `List<Int>` of **81 cells**; index `row * 9 + column`, zero-based. `0` is empty; `1..9` are digits. `Puzzle.givens` contains fixed clues; `Puzzle.solution` contains the full answer. Do not mutate a given.
- `Sudoku.generate(difficulty, seed)` is deterministic for a seed. **Easy 42 / Medium 36 / Hard 30** (`Difficulty.clues`) build a completed board, remove clues, and keep each removal only while `countSolutions(board) == 1`. These three are clue-count based, not technique-rated. **Expert, Extreme, Diabolical, Diabolical+** (`Difficulty.bank`) pick a random entry from `PuzzleBank` and apply `Sudoku.transform`: digit relabeling, band/stack and in-band row/column shuffles, and an optional transpose. This keeps uniqueness and the solving techniques the same; the solution comes from `solve`. Each bank tier's Sukaku Explainer rating band is `Difficulty.ratingRange`: Expert 4.0–5.9, Extreme 6.0–6.9, Diabolical 7.0–8.4, Diabolical+ 8.5+. Tiers must not overlap. Preserve uniqueness when changing generation.
- `PuzzleBank` reads Java resources at `/com/sarge841/woku/puzzles/<bank>.txt` (5,000 puzzles per tier, `<81 digits> <rating>` per line), so the same data works in unit tests and the APK. The source is the public-domain Sudoku Exchange Puzzle Bank (Unlicense). `scripts/build_puzzle_bank.py` downloads it to a temp directory, makes a seeded selection, re-verifies uniqueness, and rewrites the files. Do not hand-edit them.
- `Sudoku.candidates(values, index)` excludes digits in the same row, column, **and 3×3 box**; a filled cell has no candidates. `fastPencil()` replaces notes on all empty cells with these candidates, and records the entire grid as **one** undo step. It can overwrite manual notes; Undo must restore them.

## GameState invariants

- `GameState` is immutable. Board changes record a `BoardSnapshot(values, notes)` in `history`, clear `future`, and cap history at 200 snapshots. Undo/redo restore both the value and **whole note sets**; an edit after Undo invalidates Redo.
- When `livesEnabled` is true (default), a wrong nonzero placement (compared to `puzzle.solution[index]`) deducts one life and is shown in red. Clearing with `0` does not. A life spent is **not refunded by Undo**. Three mistakes result in `LOST` when `livesEnabled` is true; when `livesEnabled` is false, wrong placements still highlight in red (`DANGER` color) but do not deduct lives or block moves. An exact match to the solution results in `WON`. Moves are blocked after a terminal state.
- **Hide mistakes until checked** (`AppSettings.hideMistakesUntilChecked`, default **off**) passes `hideMistakes = true` into the rules. In that mode, `place` never deducts a life. `showsMistake` is true only for cells whose current value matches `revealedMistakes`. `digitCount`/`isDigitComplete`/`nextIncompleteDigit`/`progressCount` count placements instead of correct placements. `fastComplete` fills only empty cells, so wrong entries remain. The UI also suppresses the mistake sound, strong haptic, and correctness-only chime. `checkMistakes(livesEnabled)` replaces `revealedMistakes` with every currently wrong cell. It deducts one life per newly revealed cell/value (re-checking the same mistake is free) and does not add an undo step. The setting changes no rules when off.
- Notes can be toggled only in empty cells while playing. Placing a nonzero value clears that cell's notes and removes that digit from the notes of all peer cells in the same row, column, and 3×3 box; Undo must bring all those notes back. When 9 or fewer cells remain (`remainingCount in 1..9`), `fastComplete()` fills the board with `puzzle.solution` and clears all notes in one undoable step. `tick()` advances elapsed seconds only while playing.

## UI and storage

- `MainActivity` holds transient `SelectionState` (`selectedCell`, `selectedDigit`, `pencil`, `viewOnly`, and annotation mode `SelectionMode.DIGIT | COLOR | LINE` with `selectedColor` and `lineStyle`) and persistent `AppSettings` (`livesEnabled`, `hideMistakesUntilChecked`, `keepScreenOn`, `autoAdvanceDigit`, `hapticsEnabled`, `soundVolume`, `ThemePalette`, and `customThemes`; encoded as version `5`, versions 1–4 still decode) in Compose. Tapping a digit in the bottom bar selects that digit and clears `selectedCell` (never modifying a cell); long-pressing the selected digit deselects it and removes number highlighting. Completed digits (`isDigitComplete(digit)`) render darkened/greyed out using customizable `COMPLETED_DIGIT_SURFACE` and `COMPLETED_DIGIT_TEXT` color slots. In Color mode, tapping cells applies or toggles a circular background tint; in Line mode, tapping two cells connects them with a solid or dotted line (whose color is customized via `ColorSlot.ANNOTATION_LINE`). Each mode includes a focused "Clear" action that clears all annotations of that type (`clearAllCellColors` or `clearAllLines`) with full undo/redo support. Tapping a cell that already has a placed digit selects both that cell and its digit (without overwriting the cell). Tapping an empty cell while a digit is selected places that digit (or toggles its note in pencil mode), unless `viewOnly` mode is active, in which case it only selects the cell for safe inspection. In Pencil mode with a selected digit, dragging across the board immediately flips that digit's note on each newly visited empty cell along the path, recording only the first cell change in `history` (`recordHistory = firstCellInGesture`) so the entire drag gesture undoes in one step. When `autoAdvanceDigit` is enabled (default) and placing a digit completes all 9 correct placements of that digit, `selectedDigit` automatically advances to `nextIncompleteDigit(digit)` (wrapping `1..9`, or `null` when the board is complete). `viewOnly` and `pencil` are mutually exclusive toggles. Progress (`progressCount(hideMistakes)/81`) is shown next to the timer at the top left, and a **Fast complete** button is displayed when `canFastComplete` is true (`1..9` remaining). With hidden mistakes, a **Check for mistakes** button appears below the action rows, and the status line shows the check result or "board full". Starting a new puzzle runs `Sudoku.generate(level)` on `Dispatchers.Default` while displaying a `CircularProgressIndicator` dialog. Settings is opened via the gear icon on the far right of the top bar, with a sound volume slider (`SoundEngine` synthesizes subtle offline PCM chimes via `AudioTrack` for correct placements, digit completions, note toggles, mistakes, and a victory arpeggio) and a dedicated **Appearance** sub-dialog supporting built-in and user-saved themes (`SavedTheme`), color swatches, an HSV color wheel + brightness slider, and `#RRGGBB` hex input. Subtle haptics (`LocalView.current.performHapticFeedback`) fire on interactions when `hapticsEnabled` is true.
- SharedPreferences name `woku`: `game` holds `SaveCodec.encode(game)`; `settings` holds `AppSettings.encode()`; `best_<DIFFICULTY_NAME>` (`BestTimes.key`) holds integer completion seconds, updated only for a newly won game if faster. `best_version` (`BestTimes.CURRENT_VERSION`, now 2) runs one-time resets on startup: moving from 1 to 2 deleted Expert/Extreme/Diabolical records because those tiers were redefined. Bump the version and extend `keysToReset` if a tier's meaning changes again. The timer advances during active composition; it does not account for time away from the app.
- `SaveCodec` currently writes format version `3`: puzzle, difficulty, lives, elapsed time, current board, undo/redo stacks, `revealedMistakes` (`cell:digit,…`), `cellColors` (`cell:colorIndex,…`), and `lines` (`from-to:style,…`). Versions `1` and `2` saves still decode. Preserve old-save compatibility or explicitly implement migration when modifying the format. `decode` returns `null` on invalid saves, leading to a new Easy puzzle; do not casually drop user progress.
- Dark colors and the single-screen Compose layout are in `MainActivity.kt`. There is no network permission, backend, account, or external database. Keep these properties unless the task asks otherwise.
