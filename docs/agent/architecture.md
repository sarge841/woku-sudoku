# Architecture and behavior contracts

## Board and puzzle

- A board is a `List<Int>` of **81 cells**; index `row * 9 + column`, zero-based. `0` is empty; `1..9` are digits. `Puzzle.givens` contains fixed clues; `Puzzle.solution` contains the full answer. Do not mutate a given.
- `Sudoku.generate(difficulty, seed)` creates a completed valid board, removes clues, and retains each removal only while `countSolutions(board) == 1`. Clue targets are Easy 42, Medium 36, Hard 30, Expert 26, Extreme 23, and Diabolical 17 (generated via randomized symmetry/digit permutations of verified 17-clue minimal Sudoku templates). These levels are clue-count based, **not** rated by solving technique. Preserve uniqueness when changing generation.
- `Sudoku.candidates(values, index)` excludes digits in the same row, column, **and 3×3 box**; a filled cell has no candidates. `fastPencil()` replaces notes on all empty cells with these candidates, and records the entire grid as **one** undo step. It can overwrite manual notes; Undo must restore them.

## GameState invariants

- `GameState` is immutable. Board changes record a `BoardSnapshot(values, notes)` in `history`, clear `future`, and cap history at 200 snapshots. Undo/redo restore both the value and **whole note sets**; an edit after Undo invalidates Redo.
- When `livesEnabled` is true (default), a wrong nonzero placement (compared to `puzzle.solution[index]`) deducts one life and is shown in red. Clearing with `0` does not. A life spent is **not refunded by Undo**. Three mistakes result in `LOST` when `livesEnabled` is true; when `livesEnabled` is false, wrong placements still highlight in red (`DANGER` color) but do not deduct lives or block moves. An exact match to the solution results in `WON`. Moves are blocked after a terminal state.
- Notes can be toggled only in empty cells while playing. Placing a nonzero value clears that cell's notes and removes that digit from the notes of all peer cells in the same row, column, and 3×3 box; Undo must bring all those notes back. When 9 or fewer cells remain (`remainingCount in 1..9`), `fastComplete()` fills the board with `puzzle.solution` and clears all notes in one undoable step. `tick()` advances elapsed seconds only while playing.

## UI and storage

- `MainActivity` holds transient `SelectionState` (`selectedCell`, `selectedDigit`, `pencil`, and `viewOnly`) and persistent `AppSettings` (`livesEnabled`, `autoAdvanceDigit`, `hapticsEnabled`, `soundVolume`, `ThemePalette`, and `customThemes`) in Compose. Tapping a digit in the bottom bar selects that digit and clears `selectedCell` (never modifying a cell); long-pressing the selected digit deselects it and removes number highlighting. Completed digits (`isDigitComplete(digit)`) render darkened/greyed out using customizable `COMPLETED_DIGIT_SURFACE` and `COMPLETED_DIGIT_TEXT` color slots. Tapping a cell that already has a placed digit selects both that cell and its digit (without overwriting the cell). Tapping an empty cell while a digit is selected places that digit (or toggles its note in pencil mode), unless `viewOnly` mode is active, in which case it only selects the cell for safe inspection. In Pencil mode with a selected digit, dragging across the board immediately flips that digit's note on each newly visited empty cell along the path, recording only the first cell change in `history` (`recordHistory = firstCellInGesture`) so the entire drag gesture undoes in one step. When `autoAdvanceDigit` is enabled (default) and placing a digit completes all 9 correct placements of that digit, `selectedDigit` automatically advances to `nextIncompleteDigit(digit)` (wrapping `1..9`, or `null` when the board is complete). `viewOnly` and `pencil` are mutually exclusive toggles. Progress (`correctCount/81`) is shown next to the timer at the top left, and a **Fast complete** button is displayed when `canFastComplete` is true (`1..9` remaining). Starting a new puzzle runs `Sudoku.generate(level)` on `Dispatchers.Default` while displaying a `CircularProgressIndicator` dialog. Settings is opened via the gear icon on the far right of the top bar, with a sound volume slider (`SoundEngine` synthesizes subtle offline PCM chimes via `AudioTrack` for correct placements, digit completions, note toggles, mistakes, and a victory arpeggio) and a dedicated **Appearance** sub-dialog supporting built-in and user-saved themes (`SavedTheme`), color swatches, an HSV color wheel + brightness slider, and `#RRGGBB` hex input. Subtle haptics (`LocalView.current.performHapticFeedback`) fire on interactions when `hapticsEnabled` is true.
- SharedPreferences name `woku`: `game` holds `SaveCodec.encode(game)`; `settings` holds `AppSettings.encode()`; `best_<DIFFICULTY_NAME>` holds integer completion seconds, updated only for a newly won game if faster. The timer advances during active composition; it does not account for time away from the app.
- `SaveCodec` currently uses format version `1`. It stores puzzle, difficulty, lives, elapsed time, current board, and undo/redo stacks. Preserve old-save compatibility or explicitly implement migration when modifying the format. `decode` returns `null` on invalid saves, leading to a new Easy puzzle; do not casually drop user progress.
- Dark colors and the single-screen Compose layout are in `MainActivity.kt`. There is no network permission, backend, account, or external database. Keep these properties unless the task asks otherwise.

Add focused regression tests for new rules and save changes; avoid using only a successful APK build as evidence that the behavior works.
